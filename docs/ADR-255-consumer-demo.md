# ADR-255: исполняемая consumer demo для task и итогового epic

Дата: 2026-09-28. Задача: #255. Epic: #248.

## Статус

Принято для подготовки локальной демонстрации наблюдаемого изменения.

## Решение

`tools/agent_consumer_demo.py` принимает закрытый JSON plan и либо фиксирует
`DEMO_NOT_APPLICABLE` с непустым основанием, либо выдаёт одну копируемую
команду `python - << 'PYEOF' ... PYEOF`. Plan связывает task с исходным
`main` SHA, текущим roadmap SHA, двумя argv-сценариями и только именами
параметров. Абсолютные пользовательские пути, значения параметров и реальный
input в plan не допускаются.

Команда при локальном запуске владельцем заранее запрашивает repository,
реальный input и все необходимые параметры. Затем она проверяет закреплённые
commit SHA и неизменность roadmap ref, создаёт два временных detached worktree
и два отдельных venv, после чего на одном и том же input сначала выполняет
сценарий под заголовком `СТАРЫЙ СПОСОБ`, затем эквивалентный сценарий под
заголовком `НОВЫЙ СПОСОБ`. Команды передаются в `subprocess` как argv без
shell. Временные worktree удаляются best-effort в `finally`; исходный input не
копируется в них и не читается генератором.

Для `consumer_visible=true` assessment имеет статус
`CONSUMER_DEMO_READY`; это означает только, что команда подготовлена и её
форма проверена. Это не утверждение о фактическом результате на реальном
input. Фактический запуск и подтверждение владельца требуются на финальном
этапе epic. Для документационного или иного изменения без наблюдаемого
поведения допускается только явный `DEMO_NOT_APPLICABLE` с причиной.

Фаза `DEMO` в `tools/agent_epic_loop.py` принимает лишь закрытый assessment с
baseline SHA и roadmap SHA, равным уже подтверждённому post-merge SHA.
`DEMO_PENDING`, stale SHA, неизвестные поля или пустое основание оставляют
loop в `BLOCKED` и не допускают `TASK_DONE`.

## Security и ограничения

- Реальные input, значения параметров и результаты остаются на машине
  владельца и не включаются в GitHub, CI, prompts, checkpoint или assessment.
- Secret-параметры вводятся локально через скрытый prompt, но вызываемая
  consumer-команда отвечает за дальнейшую безопасную обработку значения.
- Генератор не доказывает semantic equivalence двух argv-сценариев; она
  проверяется при review plan и владельцем при итоговом запуске.
- Локальные worktree и venv изолируют код двух revisions, но используют один
  OS account и не являются security sandbox.

## Не входит

Автоматическое чтение реального payload, публикация demo output, изменение
публичных Library/`pgw` контрактов, финальный roadmap PR/merge (#256),
production E2E pilot (#257), version bump и release.
