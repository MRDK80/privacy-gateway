# Формат токенов

Документ описывает формат токенов, которыми Privacy Gateway заменяет
обнаруженные сущности, и поведение при восстановлении. Состояние
соответствует реализованным этапам Э1–Э8.

## Синтаксис токена

```
[TYPE_N]
```

- `TYPE` — идентификатор типа сущности в верхнем регистре;
- `N` — порядковый номер, целое число начиная с `1`, **без ведущих нулей**.

Примеры корректных токенов: `[PERSON_1]`, `[EMAIL_2]`, `[HOST_10]`.

Токенизатор строит токен как `f"[{type_key}_{counter}]"`, где `type_key` —
значение `EntityType`, а `counter` — счётчик соответствующего типа.

При восстановлении содержимое скобок проверяется регулярным выражением:

```
^[A-Z][A-Z0-9]*_[1-9][0-9]*$
```

Отсюда следуют два практических правила:

- запись с ведущими нулями (`[PERSON_001]`) синтаксически **невалидна** и
  классифицируется как искажённый токен;
- номер `0` и пустой номер недопустимы, нумерация всегда начинается с `1`.

Синтаксическая валидность и известность типа — разные проверки. Регулярное
выражение допускает произвольный идентификатор из заглавных букв и цифр,
поэтому токен может быть корректен по форме, но не соответствовать ни одному
значению `EntityType` и ни одной записи manifest.

## Типы сущностей

Перечень типов задаётся `EntityType` в `models.py`.

| Тип | Категория сущности |
|-----|--------------------|
| `PERSON` | Физическое лицо |
| `ROLE` | Должность или роль |
| `ORG` | Юридическое лицо или организация |
| `DEPARTMENT` | Внутреннее подразделение или отдел |
| `EMAIL` | Адрес электронной почты |
| `PHONE` | Номер телефона |
| `HOST` | Имя хоста, сервер или IP-адрес |
| `ENDPOINT` | URL, URI или сетевой эндпоинт |
| `RESOURCE` | Путь в файловой системе или ресурс хранилища |
| `SYSTEM` | Внутренняя система или приложение |
| `PROJECT` | Внутреннее название или код проекта |
| `AMOUNT` | Денежная сумма или финансовый показатель |
| `METRIC` | KPI или значение метрики |
| `DOCUMENT` | Идентификатор документа, номер договора или код ссылки |
| `DATE` | Конкретная дата или диапазон дат |
| `DURATION` | Период времени или продолжительность |
| `ENVIRONMENT` | Метка среды развёртывания |

Наличие типа в перечне не означает, что для него существует детектор.
Фактическое покрытие regex-детекторами и словарями описано в
[`detection.md`](detection.md); типы `METRIC`, `DOCUMENT` и `DURATION`
детекторами в текущей реализации не выделяются.

## Правила нумерации

- Счётчик ведётся **отдельно для каждого типа** и начинается с `1`.
- Область действия счётчика — **один документ за один вызов** `prepare`
  (ADR-04, вариант A). Счётчики живут в экземпляре токенизатора и на диск не
  выносятся.
- Один и тот же объект в пределах документа получает один и тот же токен.
- Между вызовами нумерация **не сохраняется**: `[EMAIL_1]` в двух разных
  запусках может соответствовать разным значениям.
- Разные объекты никогда не объединяются автоматически, даже если выглядят
  похоже.
- Обратная подстановка выполняется только по точному совпадению строки токена.

Соответствие «токен → значение» хранится в зашифрованном manifest; метаданные
запуска и `manifest_sha256` — в route. Оба артефакта размещаются в рабочем
каталоге, заданном вызовом.

## Поведение при восстановлении

Восстановление реализовано в Э7. Ответ внешнего обработчика считается
недоверенным входом, поэтому каждый кандидат на токен классифицируется:

| Класс | Условие |
|-------|---------|
| Известный | Синтаксис валиден, токен присутствует в manifest |
| Неизвестный | Синтаксис валиден, в manifest записи нет |
| Искажённый | Синтаксис не соответствует регулярному выражению |
| Пропавший | Токен есть в manifest, но отсутствует в тексте ответа |
| Дублированный | Известный токен встречается более одного раза |

Строгий режим включён по умолчанию: неизвестный или искажённый токен приводит
к отказу, выходной файл не создаётся. Мягкий режим включается явным
`--lenient` — такие кандидаты остаются в тексте без изменений и попадают в
предупреждения. Пропавший токен сам по себе отказа не вызывает, дублированный
известный токен заменяется во всех вхождениях; оба отражаются в отчёте.

Отчёт направляется в stderr и содержит только токены, счётчики и
предупреждения — восстановленные значения в него не попадают.

Строгий токенный отказ имеет отдельный код завершения `5`, отделённый от кода
`3` в Э8 (ADR-21).

## Регистрозависимость

Токены регистрозависимы (ADR-19): `[EMAIL_1]` и `[email_1]` не эквивалентны.
Изменение регистра считается искажением, а не альтернативной записью того же
токена. Это же относится к записям без скобок (`PERSON_1`) и с другим
разделителем (`[PERSON-1]`).

## Ограничение безопасности

Токен никогда не содержит фрагментов исходного значения. Запись вида
`[PERSON_Иванов]` недопустима: она не проходит проверку синтаксиса и
классифицируется как искажённая.
