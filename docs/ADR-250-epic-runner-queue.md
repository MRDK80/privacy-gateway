# ADR-250: очередь задач epic-runner и follow-up plan

Дата: 2026-09-27. Задача: #250. Epic: #248.

## Статус

Принято для read-only планирования очереди. GitHub write в эту задачу не
входит.

## Решение

`tools/agent_epic_queue.py` пересчитывает очередь только из свежего snapshot
структурных `parent` и `blockedBy`. Утверждённый порядок передаётся отдельно
от недоверенного текста issue. В каждый момент выбирается не более одной
открытой ready task: первая по утверждённому порядку, у которой нет открытого
blocker. Закрытые задачи остаются историей, но не входят в remaining queue.

Неизвестный parent, дубликат task, dependency cycle и отсутствие ready task
дают fail-closed `BLOCKED`. Открытая структурная child task, отсутствующая в
утверждённом порядке, либо порядок, противоречащий dependency, дают
`NEEDS_DECISION`. `FINAL_GATE` допустим только когда открытых структурных
children не осталось. После каждого `TASK DONE` требуется новый snapshot;
предыдущий план не доказывает, что очередь не изменилась.

Follow-up сначала дедуплицируется по закреплённому provenance. Проверенный
parent текущего epic классифицируется как `blocking-current-epic`, проверенный
другой epic — как `nonblocking-other-epic`; отсутствующий или неизвестный
parent — `needs-owner`. Лимит исчерпанных созданий требует решения владельца.
Результат является только планом: создание issue и структурная привязка
относятся к будущему trusted delivery driver и требуют действующего мандата.

## Не входит

GitHub write, изменение parent/dependency, merge, закрытие задач, runtime loop,
публичные Library/`pgw` API, JSON-контракты существующих инструментов, версия и
release.
