# ADR-432 — Подключение утверждённого локального NER

Решение о модели принято в ADR-473, контракт LOC — в ADR-431. Включение
явное через `local_ner.model_dir` в существующей конфигурации сущностей.
Путь разрешается относительно YAML. Без этой настройки используется
существующий детектор.

Модель Gather INT8 и токенизатор читаются из заранее заполненного локального
каталога. Рантайм сверяет SHA-256 обоих файлов и данных двух моделей #445.
Пакеты ONNX Runtime 1.23.2, tokenizers 0.22.2, spaCy 3.8.18 и модели RU/EN
3.8.0 предоставляет оператор в отдельном окружении. NumPy предоставляет
ONNX Runtime. Импорт этих компонентов происходит при первом вызове
включённого детектора. Сессия запускается на CPU с одним потоком и
переиспользуется в пределах процесса. Модели #445 загружаются при первом
вызове перепроверки. Используется установленный локальный комплект.

Ошибки конфигурации, зависимости, чтения, контрольной суммы, загрузки,
вывода модели или инференса останавливают detect и prepare через
существующий путь ConfigurationError. Сообщение не содержит исходный текст,
найденные значения или исключения стороннего рантайма.

Объединение сохраняет приоритет секретов и базового детектора. Затем
применяются правила ADR-473. Безусловная блокировка действует и для
модельного интервала, закрытого более приоритетной находкой. Prepare
проверяет покрытие каждого принятого
модельного интервала (включая снятый при объединении) интервалами,
действительно предназначенными для токенизации. При разрыве покрытия
подготовка блокируется до публикации. Независимая проверка защищённого
текста остаётся этапом перед публикацией.

## Проверка интеграции

На v2, v3 и раскрытых корпусах #469, #471 и #473 штатный путь детекции
воспроизвёл метрики ADR-473 по всем шести группам. Все 30 групп прошли
пороги 80% precision и 75% recall по точным интервалам и типам.
Отдельно оценён вывод prepare. Учитывалось покрытие каждого размеченного
вхождения на исходных смещениях. Повтор имени в другом месте текста
учитывался отдельно.

| Корпус | Успешных prepare | С открытым значением | Заблокировано |
| --- | ---: | ---: | ---: |
| v2 | 77 | 9 | 3 |
| v3 | 79 | 8 | 1 |
| #469 | 80 | 7 | 0 |
| #471 | 80 | 10 | 0 |
| #473 | 80 | 7 | 0 |
| Итого | 396 | 41 | 4 |

Из 44 открытых размеченных вхождений 41 остались открыты целиком и три
частично. Для 14 GLiNER не предложил пересекающегося интервала. Для девяти
он предлагал только другие границы или тип. Для 21 точный интервал был
снят на этапе перепроверки. В успешно подготовленных документах не было
открытых точных интервалов, принятых модельной связкой. Ещё 20 размеченных
вхождений были покрыты целиком при несовпадении типа или границ.
Три из четырёх отказов произошли из-за неполного покрытия известных
модельных интервалов при объединении и маршрутизации. Четвёртый отказ
относится к действующим блокировкам. Все 396 успешных локальных
восстановлений вернули исходный синтетический текст.

Успех prepare подтверждает применение политики к найденным интервалам.
Проверка перед передачей требуется и при включённом NER.

### Ресурсные замеры

По профилю #429 на одном логическом ядре Ryzen 5 5600 измерен штатный
`detect_entities`, включая базовый детектор, инференс, перепроверку и
объединение. На свежий процесс приходится 1800 измерений после прогрева.
RSS включает загрузку модели. Использованы Python 3.12.3 и один поток
для численных библиотек. Три прогона прошли бюджет #428.
