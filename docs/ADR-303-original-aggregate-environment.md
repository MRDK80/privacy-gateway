# ADR303 supplement: original aggregate environment reporting source

Owner-approved bounded design; this source is a private implementation draft pending independent review and execution. Separate from owner-source v4 and completed B2. No actual installation/activation/provider/main merge, gate rerun, extra role calls, counter refund or runtime mandate expansion.

## Confirmed source gap

AggregateReview source is a closed six-field original (identity,request,policy,session_id,output,settings_source). Gate evidence has snapshot/check results, no Python environment. GhTaskTransport.pr_body requires environment.python_version alongside gate/review and source-derived supported Python matrix. Existing legacy FinalRuntime captures platform.python_version at original execution, but config8 cannot use its approval1/verified-lesson path. Install/readiness checks do not retain an aggregate-specific original Python version. Reconstructing a cached aggregate report from the resume process version would invent historical evidence.

## Bounded original source, no approving status

Keep the six-field aggregate source and public/config/mandate shapes unchanged. Add exactly one closed internal1.0 original at the fixed existing private SourceStore path final-preparation/sources/environment-<digest(counter.identity)>.json. It has keys EXACT schema_version(1.0),kind(FINAL_AGGREGATE_ENVIRONMENT),repository,epic,mandate_digest,launch_digest,preparation_identity_digest,input_digest,review_source_digest,launcher_python_version,launcher_executable_sha256,record_digest.

Identity/hash/integer validation reuses existing final records rules. preparation_identity_digest is digest(original aggregate identity), input_digest equals original ordinal1 reservation input, review_source_digest is digest(the complete source-verified six-field aggregate source). The three repository/launch/profile/native/CI identity chains remain original and current-bound. record_digest uses existing canonical content hash excluding itself. launcher_python_version is the observed full three-component version string, not the requires-python range or a schema default. executable hash is SHA256 of the original resolved launcher executable bytes; no path, environment variables, argv secrets or diagnostics are exported.

The pinned original AggregateReview producer captures its own Python version and resolved executable hash immediately before the actual aggregate gate, retains them only in memory, and rechecks executable hash before publication. Failure/unknown version/changed executable blocks. This fact is explicitly the Python launcher of that aggregate gate, not a claim that every subprocess, hook environment or synthetic fixture used that interpreter. Reporting labels must preserve that scope; supported matrix is still read separately from pinned pyproject/workflow. If another reporting requirement needs an unrecorded subprocess fact, block it rather than infer it from this launcher source.

Only the original fixed producer writes the environment record under the already-held original seed+supervisor locks, original source guard and consumed ordinal1 reservation, alongside its genuine complete review cache and before first COMPLETED publication. Its bindable review_source_digest is available after the actual original native result. No environment file is created at zero initialization, by a model/assessment/caller, from resume platform values or from an operator report. No existing consumed state is backfilled, copied, resealed or reset. Missing/partial/conflicting environment evidence for a spent call blocks preparation/reporting; it cannot trigger a replacement gate/model call or refund.

Strict config8 pre-import completed native-chain admission and the fixed completed-source reader must validate this bounded original as well as the unchanged review/settings/reservation graph. Existing zero namespace absence, first-completion deadline, UNKNOWN and rollback/STOP/expiry rules remain. Existing sources cap=max_artifact_bytes/no-follow/private/single-link/duplicate-key protections apply. New record is not a grant and no status field can authorize a gate/effect. Legacy1–7 unchanged; earlier config8 synthetic spent states without this new original are deliberately not silently migrated.

## Assessment/report and recovery

The fixed assessment reconstruction includes BOTH the original passing gate evidence and this source-verified environment record in its local_gate_digest projection; no new assessment fields or caller-selected digest. Candidate/preparation/PR identity then binds that digest as usual. Existing B2 read_completed_aggregate_owned can retain its six-field return contract; a separate fixed owned reader may retrieve the environment fact using the same completed graph checks. No generic path/source-verifier callback or mode/skip flag is exposed. CI refresh/resume uses the original environment source, never recaptures its value; changed current executable is not substituted for historical data. Fresh current environment/readiness, if needed for a new action, is checked independently and cannot rewrite historical facts.

The record/cache/COMPLETED sequence promises no cross-file transaction or stronger crash durability. Any partial crash graph remains fail-closed and original calls remain consumed. Read-only reconciliation preserves source facts and never manufactures a missing environment original.

## Required finite synthetic verification after design approval

Current original native aggregate fixture emits the fact from the same producer; one completed cache/resume has a deliberately different current version observer and must still report original version, or refuse if original missing. Wrong version/hash/identity/input/cache linkage, duplicate/extra fields, oversize/unsafe file, partial publication/deadline and model/caller write attempt block before create/report. Default six-field review source and original first-completion behavior stay exact. No hand-authored record is treated as genuine historical gate proof. Existing preseed/native fixtures are updated only at their original creation, not by retroactively resealing consumed history. Test cases are bounded under unchanged counters, runtime/phase deadlines and role limits; no real provider or installation. Full repository gate remains only on final303sources.

The exact design received independent review and explicit owner approval in the consolidated #303 decision. Implementation still requires independent source review and verification before application. Existing B1 planning-source work is independent.
