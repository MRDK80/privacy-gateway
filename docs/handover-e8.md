# Хендовер Э8 — Privacy Gateway

Документ фиксирует остаточный долг и задачи Э8— передаётся новому исполнителю.

---

## 1. Текущее состояние

Сейчас в `main` выполнены этапы Э1–Э7. Полность конвейера:

```
пользователь
    pgw prepare <file> --out <dir>
        → prompt.txt     (tokenised text)
        → route.json     (v1.1, manifest_sha256)
        → manifest.json  (Fernet-encrypted token→value map)

    pgw restore <llm_reply> --route <dir>/route.json [--out <file>]
        → восстановленный текст
```

Ключ хранится в системном keyring (валидация backend по allowlist).

## 2. Отложенные задачи (зафиксированы в ADR)

### 2.1 Ротация ключа — MultiFernet (ADR-06, отложено с Э1)

**Проблема.** Смена Fernet-ключа делает все старые манифесты нечитаемыми. Сейчас пользователь должен вручную ротировать манифесты.

**Что сделать.**
- `keystore.py`: добавить `list_keys()` / `set_primary_key()` / `add_key()`;
  хранить список активных ключей как отдельные keyring-записи.
- `crypto.py`: передавать `MultiFernet([Fernet(k) for k in keys])` в `decrypt`;
  `encrypt` всегда использует первичный (новый) ключ.
- CLI: `pgw key rotate` — создать новый ключ, перенести старый в архив.
- Обновить ADR-06 статус: отложено → действует.

**Ограничения.** `keyring` хранит только одно значение на пару (service, username).
Для архива ключей потребуется схема именования: например,
`fernet-key-{epoch}` для отзываемых ключей.

---

### 2.2 Вариант B токенизации — глобальный реестр (ADR-04, отложено с Э1)

**Проблема.** Сейчас `[EMAIL_1]` в двух разных запусках `prepare` может
означать разные email-адреса. Для последующих разговоров полезно, чтобы
`[EMAIL_1]` всегда означал один и тот же адрес.

**Что сделать.**
- Добавить `GlobalTokenRegistry` в `tokenizer.py`— персистентный словарь
  `fingerprint → token` с атомарной записью в файл (`~/.pgw/token_registry.json`).
- Сохранить `PerDocumentStrategy` как дефолт; `GlobalStrategy` — явный opt-in через
  `--token-strategy global` или конфиг.
- Файл реестра не хранит plaintext-значения — только `fingerprint → token`.
- Обновить ADR-04 статус: отложено → действует.

**Ограничения.** Реестр — дополнительный артефакт, который может быть повреждён.
Необходима защита от рейс-условий при записи (файл в `rw-------`).

---

### 2.3 Разведение кода возврата 3 (ADR-20, отложено с Э7)

**Проблема.** Код 3 объединяет два независимых класса ошибок:
- ошибки входа/конфигурации/целостности (`ConfigurationError`);
- строгий отказ по токенам (`RestoreError`).

**Что сделать.**
- Ввести новый код, например **5**, для `RestoreError`
  (строгий отказ по неизвестному/искажённому токену).
- Код 3 остаётся за `ConfigurationError`, `InputError`.
- Обновить: `cli.py`, `ARCHITECTURE.md` (таблица кодов), ADR-20.
- **Важно:** не сломать все старые тесты, которые проверяют `code == 3`. Сначала
  обновить `test_cli_restore.py`, потом все остальные тесты.

## 4. Неизменяемые инварианты

- `manifest.json` никогда не хранит plaintext-значения и ключ в открытом виде.
- Отчёт `pgw restore` не содержит восстановленных значений.
- `verify_manifest_integrity` вызывается до `get_key` и `load_manifest` — это запрещено нарушать.
- `yaml.safe_load` остаётся единственным способом загрузки YAML.
- Токены регистрозависимы — автонормализация регистра запрещена (ADR-19).
