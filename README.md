# Privacy Gateway

Локальный CLI-инструмент для безопасной подготовки корпоративных текстов перед ручной передачей во внешнюю языковую модель. Инструмент работает полностью локально: обнаруживает ПДн и секреты, заменяет их токенами вида `[TYPE_N]`, шифрует карту соответствий и проверяет, что в подготовленном тексте не осталось чувствительных данных.

## Как это работает

Конвейер обработки (`pgw prepare`):

```
[входной текст: файл / stdin]
        │
        ▼  input_parser.py — чтение, определение кодировки
        │
        ▼  routing.py — загрузка YAML-конфига маршрутизации (yaml.safe_load)
        │
        ▼  keystore.py — получение Fernet-ключа из системного keyring
        │
        ▼  detector.py ── regex + словарь → list[DetectedEntity]
        │
        ▼  Фильтрация по RoutingConfig:
        │    block_unconditionally → немедленный BLOCKED
        │    tokenize_types → только разрешённые типы
        │
        ▼  tokenizer.py ── замена на [TYPE_N] → (токенизированный текст, TokenRecord[])
        │
        ▼  manifest.py ── Fernet-шифрование → ManifestEntry[]
        │                  manifest.json (rw-------)
        ▼  validator.py ── два прохода: негативный + позитивный
        │
        ▼  При OK — атомарная запись:
             prompt.txt    — токенизированный текст
             manifest.json — зашифрованная карта token→value
             route.json    — метаданные v1.1, счётчики и manifest_sha256
```

Ответственность модулей:

| Модуль | Назначение |
|--------|------------|
| `models.py` | Все типизированные модели данных и исключения |
| `input_parser.py` | Безопасное чтение файла или stdin |
| `detector.py` | Обнаружение ПДн и секретов (regex + словарь) |
| `tokenizer.py` | Замена сущностей на токены `[TYPE_N]` |
| `crypto.py` | Fernet-шифрование/расшифровка |
| `keystore.py` | Хранение ключа в системном keyring |
| `manifest.py` | Сборка, сохранение и загрузка зашифрованного манифеста |
| `validator.py` | Независимая проверка токенизированного текста |
| `routing.py` | Загрузка и валидация YAML-конфига маршрутизации |
| `pipeline.py` | Сквозной конвейер prepare |
| `cli.py` | Точка входа `pgw` |

## Установка

### Системные требования

- Python 3.11+
- **Linux:** установленный `gnome-keyring` или другой SecretService-совместимый демон
- **macOS:** Keychain (доступен по умолчанию)
- **Windows:** Windows Credential Vault (доступен по умолчанию)

### Linux / Linux Mint

```bash
sudo apt update
sudo apt install python3.11 python3.11-venv gnome-keyring

git clone https://github.com/MRDK80/privacy-gateway.git
cd privacy-gateway
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

### Windows (PowerShell)

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

Если политика выполнения блокирует активацию:

```powershell
.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

## Использование

### pgw detect

```bash
# Анализ файла (UTF-8 по умолчанию)
pgw detect input.txt

# Явная кодировка
pgw detect input.txt --encoding utf-8
pgw detect input.txt --encoding cp1251

# Чтение из stdin
echo "Позвоните Ивану Петрову на +7 900 000-00-00" | pgw detect -

# Свой конфиг словарей
pgw detect input.txt --config path/to/entities.yaml
```

Вывод — JSON-метаданные без исходных значений (диагностика, не гарантия).

### pgw prepare  [Э6]

```bash
# Базовый запуск
pgw prepare input.txt

# С явным выходным каталогом
pgw prepare input.txt --out ./output

# С YAML-конфигом маршрутизации
pgw prepare input.txt --routing routing.yaml

# Разрешить перезапись существующих артефактов
pgw prepare input.txt --out ./output --overwrite

# Чтение из stdin
cat input.txt | pgw prepare -

# Явная кодировка входного файла
pgw prepare input.txt --encoding cp1251
```

При статусе **OK** создаются три файла в выходном каталоге:
- `prompt.txt` — токенизированный текст без исходных значений
- `manifest.json` — зашифрованная карта token→value (права `rw-------`)
- `route.json` — метаданные запуска версии `1.1`, счётчики токенов и `manifest_sha256`

`manifest_sha256` содержит SHA-256 всех байтов финального `manifest.json`. Поле обеспечивает обнаружение рассинхронизации пары артефактов и повреждения файла манифеста. Версия `route.json` `"1.0"` поддерживается без проверки суммы для обратной совместимости.

SHA-256 без подписи не обеспечивает аутентичность и не является защитой от целенаправленной подмены: субъект, способный заменить оба файла, может пересчитать сумму. Fernet отдельно аутентифицирует зашифрованные записи манифеста, а `manifest_sha256` связывает пару файлов целиком.

При **BLOCKED** или **PENDING** файлы не создаются.

**Коды завершения:**

| Код | Значение |
|-----|-----------|
| 0 | OK — артефакты созданы |
| 2 | PENDING — требуется ручное одобрение |
| 3 | BLOCKED или ошибка конфигурации/входа |
| 4 | Ошибка keystore (ключ не найден или небезопасный backend) |
| 1 | Непредвиденная ошибка |

### Пример YAML-конфига маршрутизации

```yaml
output_dir: "./pgw_out"
overwrite: false
rules:
  tokenize:
    - EMAIL
    - PHONE
    - HOST
    - PERSON
  block_unconditionally:
    - SECRET
```

Отсутствие файла конфига — безопасные умолчания (все типы токенизируются, `overwrite: false`).

## Требования к keyring

Модули `keystore.py`, `crypto.py` и `manifest.py` требуют системного защищённого хранилища ключей.

| Платформа | Требование |
|-----------|------------|
| Linux | SecretService (gnome-keyring / KWallet) |
| macOS | macOS Keychain (встроен) |
| Windows | Windows Credential Vault (встроен) |

**Headless Linux (CI / сервер без GUI):**

```bash
dbus-run-session -- bash -c \
  'echo -n "" | gnome-keyring-daemon --unlock && pgw prepare input.txt'
```

Приложение и демон должны работать в **одной D-Bus сессии**.

Переменная окружения `PGW_KEYRING_BACKEND` позволяет задать backend по FQCN класса. Значение также проходит валидацию по allowlist безопасных backend-ов.

## Безопасность

### От чего защищает

Privacy Gateway снижает риск случайной передачи ПДн (email, IP-адреса, телефоны, имена, пути) и распространённых секретов (пароли, API-ключи, PEM-блоки, строки подключения) во внешнюю LLM. Исходные значения шифруются локально; в манифесте и в выводе инструмента открытых данных нет.

### Безопасность конфига маршрутизации  [Э6]

- YAML загружается только через `yaml.safe_load` — защита от YAML-инъекции
- Неизвестные ключи в конфиге — немедленная ошибка (fail closed)
- Конфиг не может отключить проверку секретов

### От чего **не** защищает

- Многострочные секреты, распределённые по нескольким строкам
- Пароли и токены, не соответствующие keyword-паттернам
- Косвенную идентификацию через комбинацию обезличенных полей
- Намеренную утечку через сам LLM-провайдер
- Атаки на систему до/после обработки текста инструментом

Подробнее — в [`docs/SECURITY.md`](docs/SECURITY.md).

## Ограничения и известные проблемы

- **Ротация ключа делает старые манифесты нечитаемыми.** `MultiFernet` не реализован (отложен до Э8).
- **Токены не стабильны между запусками.** Стратегия вариант A: нумерация ведётся внутри одного документа. `[EMAIL_1]` в двух разных запусках может соответствовать разным адресам.
- **`pgw detect` — диагностика, не гарантия.** Результат команды не является разрешением передавать исходный текст модели.
- **`PENDING` — не мягкий OK.** Текст со статусом `PENDING` нельзя отправлять автоматически без ручного одобрения.

## ⚠️ Политика безопасности репозитория

**Не добавляйте в репозиторий реальные корпоративные данные** — имена, email, IP-адреса, имена серверов, финансовые данные и любую другую идентифицирующую информацию. В примерах используйте только синтетику: `user@example.com`, `192.0.2.10`, `2001:db8::1`, `+7 900 000-00-00`.
