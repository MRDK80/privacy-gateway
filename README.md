# Privacy Gateway

Локальный CLI-инструмент для безопасной подготовки корпоративных текстов перед ручной передачей во внешнюю языковую модель. Инструмент работает полностью локально: обнаруживает ПДн и секреты, заменяет их токенами вида `[TYPE_N]`, шифрует карту соответствий и проверяет, что в подготовленном тексте не осталось чувствительных данных.

## Как это работает

Конвейер обработки:

```
[входной текст: файл / stdin]
        │
        ▼  input_parser.py — чтение, определение кодировки
        │
        ▼  detector.py ── regex + словарь → список DetectedEntity
        │
        ▼  tokenizer.py ── замена на [TYPE_N] → (токенизированный текст, TokenRecord[])
        │
        ▼  manifest.py ── Fernet-шифрование исходных значений → ManifestEntry[]
        │                  keystore.py ── Fernet-ключ из системного keyring
        ▼  validator.py ── два прохода: негативный (остатки PII) + позитивный (формат токенов)
        │
        ▼  ValidationResult{ status: OK | BLOCKED | PENDING }
```

Ответственность модулей:

| Модуль | Назначение |
|--------|------------|
| `models.py` | Все типизированные модели данных и исключения |
| `input_parser.py` | Безопасное чтение файла или stdin |
| `detector.py` | Обнаружение ПДн и секретов (regex + словарь) |
| `tokenizer.py` | Замена сущностей на токены `[TYPE_N]` |
| `crypto.py` | Fernet-шифрование/расшифровка |
| `keystore.py` | Хранение ключа в системном keyring |
| `manifest.py` | Сборка, сохранение и загрузка зашифрованного манифеста |
| `validator.py` | Независимая проверка токенизированного текста |
| `cli.py` | Точка входа `pgw` |

## Установка

### Системные требования

- Python 3.11+
- **Linux:** установленный `gnome-keyring` или другой SecretService-совместимый демон
- **macOS:** Keychain (доступен по умолчанию)
- **Windows:** Windows Credential Vault (доступен по умолчанию)

### Linux / Linux Mint

```bash
sudo apt update
sudo apt install python3.11 python3.11-venv gnome-keyring

git clone https://github.com/MRDK80/privacy-gateway.git
cd privacy-gateway
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

### Windows (PowerShell)

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

Если политика выполнения блокирует активацию:

```powershell
.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

## Использование

В текущей версии (Э1–Э5) реально работает только команда `pgw detect`.

```bash
# Справка
pgw --help
pgw detect --help

# Анализ файла (UTF-8 по умолчанию)
pgw detect input.txt

# Явная кодировка
pgw detect input.txt --encoding utf-8
pgw detect input.txt --encoding cp1251

# Чтение из stdin
echo "Позвоните Ивану Петрову на +7 900 000-00-00" | pgw detect -

# Свой конфиг словарей
pgw detect input.txt --config path/to/entities.yaml
```

Вывод — JSON без исходных значений:

```json
{
  "source": "file",
  "encoding": "utf-8",
  "entity_count": 2,
  "entities": [
    {
      "type": "PERSON",
      "start": 10,
      "end": 22,
      "confidence": "MEDIUM",
      "source": "dictionary",
      "fingerprint": "<sha256-prefix>"
    },
    {
      "type": "PHONE",
      "start": 26,
      "end": 43,
      "confidence": "MEDIUM",
      "source": "regex",
```

## Требования к keyring

Модули `keystore.py`, `crypto.py` и `manifest.py` требуют системного защищённого хранилища ключей.

| Платформа | Требование |
|-----------|------------|
| Linux | SecretService (gnome-keyring / KWallet) |
| macOS | macOS Keychain (встроен) |
| Windows | Windows Credential Vault (встроен) |

**Headless Linux (CI / сервер без GUI):**

```bash
dbus-run-session -- bash -c \
  'echo -n "" | gnome-keyring-daemon --unlock && pgw detect input.txt'
```

Приложение и демон должны работать в **одной D-Bus сессии**.

Переменная окружения `PGW_KEYRING_BACKEND` позволяет задать backend по FQCN класса. Значение также проходит валидацию по allowlist безопасных backend-ов.

## Безопасность

### От чего защищает

Privacy Gateway снижает риск случайной передачи ПДн (email, IP-адреса, телефоны, имена, пути) и распространённых секретов (пароли, API-ключи, PEM-блоки, строки подключения) во внешнюю LLM. Исходные значения шифруются локально; в манифесте и в выводе инструмента открытых данных нет.

### От чего **не** защищает

- Многострочные секреты, распределённые по нескольким строкам
- Пароли и токены, не соответствующие keyword-паттернам (`password=`, `api_key=` и т.п.)
- Косвенную идентификацию через комбинацию обезличенных полей
- Намеренную утечку через сам LLM-провайдер
- Атаки на систему до/после обработки текста инструментом

Подробнее — в [`docs/SECURITY.md`](docs/SECURITY.md).

## Ограничения и известные проблемы

- **Ротация ключа делает старые манифесты нечитаемыми.** При смене ключа необходимо загрузить манифесты со старым ключом и пересохранить с новым. `MultiFernet` не реализован (отложен до Э8).
- **Токены не стабильны между запусками.** Стратегия вариант A: нумерация ведётся внутри одного документа, состояние между запусками не сохраняется. `[EMAIL_1]` в двух разных запусках может соответствовать разным адресам.
- **`pgw detect` — диагностика, не гарантия.** Результат команды не является разрешением передавать исходный текст модели.
- **`PENDING` — не мягкий OK.** Текст со статусом `PENDING` нельзя отправлять автоматически без ручного одобрения.

## ⚠️ Политика безопасности репозитория

**Не добавляйте в репозиторий реальные корпоративные данные** — имена, email, IP-адреса, имена серверов, финансовые данные и любую другую идентифицирующую информацию. В примерах используйте только синтетику: `user@example.com`, `192.0.2.10`, `2001:db8::1`, `+7 900 000-00-00`.

Политика — в [`SECURITY.md`](SECURITY.md) и [`docs/SECURITY.md`](docs/SECURITY.md).
