# Privacy Gateway

Локальный CLI-инструмент для безопасной подготовки корпоративных текстов
перед ручной передачей во внешнюю языковую модель. Инструмент работает
полностью локально: обнаруживает ПДн и секреты, заменяет их токенами вида
`[TYPE_N]`, шифрует карту соответствий, проверяет подготовленный текст и
восстанавливает исходные значения после получения ответа LLM.

## Статус проекта

Реализованы этапы **Э1–Э7**. Этап Э8 не начат.

| Этап | Что реализовано | Статус |
|------|-----------------|--------|
| Э1 | Каркас, CI, конфиг, точка входа `pgw` | ✅ |
| Э2 | Чтение входа (файл / stdin), кодировки, кроссплатформенные пути | ✅ |
| Э3 | Детектор: regex + словарь, разрешение перекрытий, приоритеты | ✅ |
| Э4 | Токенизатор, Fernet-шифрование, keystore, манифест | ✅ |
| Э5 | Валидатор: независимый рубеж, два прохода, энтропия Шеннона | ✅ |
| Э6 | YAML-маршрутизация, `prepare`, `prompt.txt`, `route.json` | ✅ |
| Э7 | `restore`, контроль целостности и классификация токенов | ✅ |
| Э8 | `pgw key create`, `MultiFernet`, ротация ключей | 🔜 не реализовано |

**Что ещё не работает:**

- `pgw key create` не реализована;
- `MultiFernet` и автоматическая ротация ключей не реализованы.

## Как это работает

### Подготовка

Конвейер `pgw prepare`:

```text
[входной текст: файл / stdin]
        │
        ▼  input_parser.py — чтение, определение кодировки
        │
        ▼  routing.py — YAML-конфиг через yaml.safe_load
        │
        ▼  detector.py — regex + словарь → DetectedEntity[]
        │
        ▼  Фильтрация по RoutingConfig:
        │    block_unconditionally → немедленный BLOCKED
        │    tokenize_types → только разрешённые типы
        │
        ▼  tokenizer.py — замена на [TYPE_N] → TokenRecord[]
        │
        ▼  keystore.py — Fernet-ключ из системного keyring
        │
        ▼  manifest.py — Fernet-шифрование → ManifestEntry[]
        │                  manifest.json (rw-------)
        ▼  validator.py — независимые негативный и позитивный проходы
        │
        ▼  При OK — атомарная запись:
             prompt.txt    — токенизированный текст
             manifest.json — зашифрованная карта token→value
             route.json    — метаданные v1.1 и manifest_sha256
```

### Восстановление

Ответ внешней LLM считается недоверенным входом. Конвейер `pgw restore`:

```text
[ответ LLM: файл / stdin]
        │
        ▼  прочитать и проверить route.json
        │
        ▼  выбрать manifest_path:
        │    --manifest переопределяет route.json
        │    относительный путь разрешается от каталога route.json
        │
        ▼  verify_manifest_integrity()
        │    выполняется до keyring, загрузки и расшифровки
        │
        ▼  получить Fernet-ключ из keyring
        │
        ▼  загрузить и расшифровать manifest.json
        │
        ▼  классифицировать токены:
        │    известные / неизвестные / искажённые /
        │    пропавшие / дублированные
        │
        ▼  подставить известные значения
        │
        ▼  вывести отчёт без восстановленных значений в stderr
        │
        ▼  вывести текст в stdout или атомарно записать в --out
```

Ответственность модулей:

| Модуль | Назначение |
|--------|------------|
| `models.py` | Типизированные модели данных и исключения |
| `input_parser.py` | Безопасное чтение файла или stdin |
| `detector.py` | Обнаружение ПДн и секретов |
| `tokenizer.py` | Замена сущностей на токены `[TYPE_N]` |
| `crypto.py` | Fernet-шифрование и расшифровка |
| `keystore.py` | Хранение ключа в системном keyring |
| `manifest.py` | Сборка, сохранение и загрузка манифеста |
| `validator.py` | Независимая проверка токенизированного текста |
| `routing.py` | YAML-конфиг и `verify_manifest_integrity` |
| `pipeline.py` | Сквозной конвейер `prepare` |
| `restore.py` | Восстановление текста и классификация токенов |
| `cli.py` | Команды `detect`, `prepare` и `restore` |

## Установка

### Системные требования

- Python 3.11+
- **Linux:** `gnome-keyring` или другой SecretService-совместимый демон
- **macOS:** Keychain, доступный по умолчанию
- **Windows:** Windows Credential Vault, доступный по умолчанию

### Linux / Linux Mint

```bash
sudo apt update
sudo apt install python3.11 python3.11-venv gnome-keyring

git clone https://github.com/MRDK80/privacy-gateway.git
cd privacy-gateway
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
```

### Windows (PowerShell)

```powershell
py -3.11 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
```

Если политика выполнения блокирует активацию:

```powershell
.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

## Использование

### pgw detect

```bash
# Анализ файла, UTF-8 по умолчанию
pgw detect input.txt

# Явная кодировка
pgw detect input.txt --encoding utf-8
pgw detect input.txt --encoding cp1251

# Чтение из stdin
echo "Позвоните Ивану Петрову на +7 900 000-00-00" | pgw detect -

# Свой конфиг словарей
pgw detect input.txt --config path/to/entities.yaml
```

Вывод — JSON-метаданные без исходных значений. Команда предназначена для
диагностики и сама по себе не разрешает отправку исходного текста в LLM.

### pgw prepare  [Э6]

```bash
# Базовый запуск
pgw prepare input.txt

# С явным выходным каталогом
pgw prepare input.txt --out ./output

# С YAML-конфигом маршрутизации
pgw prepare input.txt --routing routing.yaml

# Разрешить перезапись существующих артефактов
pgw prepare input.txt --out ./output --overwrite

# Чтение из stdin
cat input.txt | pgw prepare -

# Явная кодировка входного файла
pgw prepare input.txt --encoding cp1251
```

При статусе **OK** создаются три файла:

- `prompt.txt` — токенизированный текст без исходных значений;
- `manifest.json` — зашифрованная карта token→value с правами `rw-------`;
- `route.json` — метаданные версии `1.1`, счётчики и `manifest_sha256`.

`manifest_sha256` содержит SHA-256 всех байтов финального
`manifest.json`. Поле обнаруживает рассинхронизацию пары артефактов и
повреждение манифеста.

Версия `route.json` `"1.0"` поддерживается без проверки суммы для обратной
совместимости. Версия `"1.1"` требует корректного `manifest_sha256`.

SHA-256 без подписи не обеспечивает аутентичность и не защищает от
согласованной подмены обоих файлов. Fernet отдельно аутентифицирует
зашифрованные записи, а `manifest_sha256` связывает пару файлов целиком.

При **BLOCKED** или **PENDING** артефакты не создаются.

### pgw restore  [Э7]

Команда принимает ответ LLM из файла либо stdin и обязательный путь к
`route.json`.

```bash
# Восстановить ответ LLM в stdout
pgw restore llm_reply.txt --route ./output/route.json

# Атомарно записать восстановленный текст в файл
pgw restore llm_reply.txt \
  --route ./output/route.json \
  --out restored.txt

# Разрешить перезапись существующего результата
pgw restore llm_reply.txt \
  --route ./output/route.json \
  --out restored.txt \
  --overwrite

# Прочитать ответ LLM из stdin
cat llm_reply.txt | pgw restore - --route ./output/route.json

# Явно переопределить путь к манифесту
pgw restore llm_reply.txt \
  --route ./output/route.json \
  --manifest ./other/manifest.json \
  --out restored.txt

# Явно включить мягкий режим
pgw restore llm_reply.txt \
  --route ./output/route.json \
  --out restored.txt \
  --lenient
```

Доступные параметры:

| Параметр | Назначение |
|----------|------------|
| `INPUT` | Ответ LLM: путь к файлу или `-` для stdin |
| `--route PATH` | Обязательный путь к `route.json` |
| `--out PATH` | Выходной файл; без параметра результат идёт в stdout |
| `--overwrite` | Разрешить замену существующего выходного файла |
| `--manifest PATH` | Переопределить `manifest_path` из `route.json` |
| `--lenient` | Оставить неизвестные и искажённые токены с предупреждениями |

Строгий режим включён по умолчанию. Неизвестный или искажённый токен
вызывает отказ с кодом 3, а результирующий файл не создаётся.

Мягкий режим включается только явным `--lenient`. Неизвестные и
искажённые кандидаты остаются в тексте без изменений и отражаются в
предупреждениях.

Токены регистрозависимы: `[EMAIL_1]` и `[email_1]` не эквивалентны.
Изменённый регистр считается искажением.

Пропавший токен — токен из манифеста, отсутствующий в ответе LLM — не
вызывает отказ сам по себе, но включается в отчёт. Дублированный известный
токен заменяется во всех вхождениях и также отмечается в отчёте.

Служебный отчёт направляется в stderr и содержит только токены, счётчики
и предупреждения. Восстановленные значения в отчёт не включаются.

### Полный цикл prepare → restore

```bash
# 1. Подготовить исходный документ
pgw prepare input.txt --out ./pgw_out

# 2. Передать во внешнюю LLM содержимое pgw_out/prompt.txt.
#    Сохранить ответ модели в llm_reply.txt.

# 3. Восстановить исходные значения
pgw restore llm_reply.txt \
  --route ./pgw_out/route.json \
  --out restored.txt

# 4. Проверить результат
cat restored.txt
```

Для имитации LLM без изменения текста:

```bash
pgw prepare input.txt --out ./pgw_out
cp ./pgw_out/prompt.txt ./llm_reply.txt

pgw restore ./llm_reply.txt \
  --route ./pgw_out/route.json \
  --out ./restored.txt

cmp input.txt restored.txt
```

Если ответ LLM не изменил структуру текста и токенов, `cmp` завершается с
кодом 0: восстановленный файл побайтово совпадает с исходным.

### Коды завершения

| Код | Значение |
|-----|----------|
| 0 | Успешное выполнение |
| 1 | Непредвиденная ошибка |
| 2 | PENDING — требуется ручное одобрение |
| 3 | BLOCKED, ошибка входа/конфигурации/целостности или строгий отказ restore |
| 4 | Ошибка keystore или отсутствие ключа |

Код 3 объединяет несколько категорий ошибок. Разведение его семантики
отложено до Э8; в Э7 существующая таблица не меняется.

### Пример YAML-конфига маршрутизации

```yaml
output_dir: "./pgw_out"
overwrite: false
rules:
  tokenize:
    - EMAIL
    - PHONE
    - HOST
    - PERSON
  block_unconditionally:
    - SECRET
```

Отсутствие файла конфига означает безопасные умолчания: все поддерживаемые
типы токенизируются, `overwrite` выключен.

## Требования к keyring

Модули `keystore.py`, `crypto.py`, `manifest.py` и `restore.py` используют
системное защищённое хранилище ключей.

| Платформа | Требование |
|-----------|------------|
| Linux | SecretService (gnome-keyring / KWallet) |
| macOS | macOS Keychain |
| Windows | Windows Credential Vault |

**Headless Linux, CI или сервер без GUI:**

```bash
dbus-run-session -- bash -c \
  'echo -n "" | gnome-keyring-daemon --unlock && pgw prepare input.txt'
```

Приложение и демон должны работать в одной D-Bus-сессии.

Переменная `PGW_KEYRING_BACKEND` позволяет задать backend по полному имени
класса. Значение также проверяется по allowlist безопасных backend.

Команда `pgw key create` пока не реализована. Ключ должен существовать в
keyring до запуска `prepare` или `restore`.

## Безопасность

### От чего защищает

Privacy Gateway снижает риск случайной передачи ПДн и распространённых
секретов во внешнюю LLM. Исходные значения шифруются локально; открытых
значений нет в `manifest.json`, `route.json` и служебном отчёте.

Результат `restore` намеренно содержит восстановленный plaintext. Его
необходимо защищать так же, как исходный документ.

### Ответ LLM

Ответ внешней LLM считается недоверенным. Модель может удалить,
продублировать, исказить или выдумать токен. Поэтому `restore` выполняет
явную классификацию токенов и по умолчанию работает в строгом режиме.

Проверка `verify_manifest_integrity` выполняется до обращения к keyring,
загрузки и расшифровки манифеста.

### Безопасность YAML-конфига  [Э6]

- YAML загружается только через `yaml.safe_load`;
- неизвестные ключи вызывают немедленную ошибку;
- конфиг не может отключить проверку секретов.

### От чего **не** защищает

- Многострочные секреты, распределённые по нескольким строкам
- Пароли и токены, не соответствующие keyword-паттернам
- Косвенную идентификацию через комбинацию обезличенных полей
- Намеренную утечку через LLM-провайдера
- Компрометацию восстановленного plaintext
- Согласованную замену `route.json` и `manifest.json` с пересчётом SHA-256
- Атаки на систему до или после обработки текста

Подробнее — в [`docs/SECURITY.md`](docs/SECURITY.md).

## Ограничения и известные проблемы

- **Ротация ключа делает старые манифесты нечитаемыми.** `MultiFernet`
  не реализован и отложен до Э8.
- **Токены не стабильны между запусками.** Нумерация ведётся внутри одного
  документа; `[EMAIL_1]` в разных запусках может означать разные значения.
- **`pgw detect` — диагностика, не гарантия.** Результат команды не разрешает
  автоматически передавать исходный текст модели.
- **`PENDING` — не мягкий OK.** Такой текст нельзя отправлять автоматически
  без ручного одобрения.
- **Код возврата 3 перегружен.** Разведение кодов отложено до Э8.
- **TOCTOU при перезаписи требует отдельной проверки.** Защита
  `--overwrite` должна быть подтверждена тестами и аудитом реализации.

## ⚠️ Политика безопасности репозитория

**Не добавляйте в репозиторий реальные корпоративные данные:** имена,
email, IP-адреса, серверы, финансовые данные и другие идентификаторы.

В примерах используйте только синтетические данные:

- `user@example.com`
- `192.0.2.10`
- `2001:db8::1`
- `+7 900 000-00-00`
